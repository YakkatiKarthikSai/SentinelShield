# SentinelShield Demonstration Guide

## Before the demonstration

```powershell
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
python -m sentinelshield.simulation
```

Expected result: all tests pass and the offline simulator stores three allowed and
six blocked sample events in `sentinelshield_events.db`.

## Demonstrate the dashboard

```powershell
python -m streamlit run dashboard.py
```

Use the local address printed by Streamlit. Explain that the dashboard reads the
same SQLite event database populated by the CLI or API.

Use the **Live request inspector** at the top of the dashboard for a more
interactive demonstration. Submit a normal search request to show an allow result,
then change the query JSON to `{"q": "7 OR 1=1"}` to show an explainable block.
The dashboard records both events immediately and updates the visual summary.

## Demonstrate the API

```powershell
python -m uvicorn sentinelshield.api:app --reload
```

Open `http://127.0.0.1:8000/docs`, then use the interactive `POST /inspect`
endpoint. Show a normal request first, then an attack-shaped request. Point out the
returned decision, rule ID, severity, field location, and evidence.

## Demonstrate real middleware protection

Stop the API, then start the protected local demo:

```powershell
python -m uvicorn sentinelshield.demo_app:app --reload
```

Open `http://127.0.0.1:8000/search?q=campus` to show a request reaching the demo
application. Then open `http://127.0.0.1:8000/search?q=7%20OR%201%3D1` to show an
HTTP 403 response generated by SentinelShield middleware. This is a local demo;
do not expose it publicly.

## Suggested viva explanation

“SentinelShield examines selected parts of an HTTP-like request against explicit,
rule-based indicators. It produces an explainable allow or block decision, stores
the event locally, and visualizes the results. It also detects request bursts and,
when an application supplies real authentication outcomes, repeated failed logins.
It is an educational prototype, so its rules are limited and it requires broader,
independent testing before any production use.”
